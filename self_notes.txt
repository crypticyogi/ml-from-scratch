Linear Regression:

What is Linear Regression?
- Finds the best fit straight line or hyperplane through data.
- Assumes relationship: y = w·x + b (for 1 feature)
  w = weight, b = bias
How do we find w and b?
- Define an error function = Mean Squared Error (MSE)
- Our goal is to find w,b that minimizes the MSE
Why not just use a formula?
- There is a closed form solution: Normal Equation
- But Gradient Descent (GD) scales better to huge datasets and is the foundation for neural networks.
Batch Gradient Descent:
1. Use ALL training examples to compute the gradient in every step.
2. Gradient = direction of steepest increase in loss.
3. Update rule: w = w − lr·(dL/dw) and b = b − lr·(dL/db) {lr = learning rate}
4. Repeat until loss stops changing (convergence)
Add-Ons Used:
- L2 Regularization (Ridge)
- Early Stopping: Stop training if loss improvement < tolerance (saves time)
Train/Test Split:
- Shuffle data, take 80% for training, 20% for testing.
- Never fit on test data, this tells us if the model generalizes.
Output Explanation:
1. A straight line is sufficient for this data.
2. Loss curve goes down and settles at the minimum.
3. Learned w and b are very close to the true (3, 2) despite noise.
4. Train and Test MSE are close: model did not overfit.
5. Code supports alpha, setting it to 0 here is correct because this simple problem doesn't need it.
6. Normal Equation = GD optimum (Both methods give the same answer, validating the implementation)


Binary Logistic Regression:

- Predicts which of the two classes an input belongs to
- Instead of outputting 0 or 1, it gives a probability using a sigmoid function
- If the probability is greater than or equal to 0.5, then we say it belongs to class 1. Else we say class 0.
- Even though the name says "Regression" it is basically used for "Classification".

Batch Gradient Descent:
Gradient: Direction in which the loss increases fastest. Hence to minimise the loss, we step in the direction opposite to that of Gradient.
Batch: Computing gradient using the entire dataset at once (not one point at a time).
Descent: Repeatedly take small steps downhill on the loss surface.

In the code, the loop does this every epoch (iteration):
1. Find probabilities of all training examples
2. Compute the average error (loss)
3. Calculate how much each weight and the bias contributed to that error (the gradient)
4. Repeat until the loss stops improving or you hit the max epochs.

Testing it on 2D data:
- Each input example has two numerical features
- Every data point can be plotted as a single dot on a flat plane
- The code generates two fake clusters of points (Gaussian blobs)
- Because the data is 2D, you can draw the model's decision boundary as a line (or curve) and actually see how well it separates the two classes.

Studying Output:
- Every 200 passes through the full training set, it outputs average loss
- The number is going down, this means model is getting better at predicting labels
- The model stopped early (at around 1600 instead of 2000 epochs): this shows there is nothing meaningful left to learn

We learnt the formulas for: Accuracy, Precision and Recall in Elements of Machine Learning Course (Prof. Isabella Valera)
1. Accuracy: 100% predicted correctly
2. Precision: When it predicted class 1, it was right every time
3. Recall: It found every actual class 1 in the test set.
F1: Harmonic mean of Precision and Recall.

Why so Perfect Confusion Matrix (Machine Learning, SS2026: Prof. Valera): This is an easy problem, so logistic regression nails it. Real world messy data rarely scores 100%.

We get "Final Loss = 0.016271", which means the model is not confident 100% on every single data point. This measures the remaining uncertainty on the training set. It is very low, which is good.

We got Learned Weights and Bias: Learned weights: [4.4523 4.441 ], bias: -0.5103
- Hence the boundary equation becomes 4.4523·x1 + 4.441·x2 - 0.5103
- Because the two weights are nearly equal, the boundary is roughly a diagonal line slicing between your two blobs.
- The negative bias shifts that line so it sits between the clusters rather than passing through the origin.

Output Graphs:
1. Since logistic regression is a linear model, the boundary between blue and red is a straight line.
2. The curve drops very fast in the first 50 epochs then keeps slowly bending downward until it flattens out around epoch 400.
3. The improvements afterwards are tiny which is exactly why the code triggered early stopping at epoch 1600 instead of running all 2000 epochs.
- The model had already learned everything useful.
4. The loss curve shows successful learning
5. The decision surface shows that learning translated into a clean separator between the two classes with zero mistakes on unseen test data.

Polynomial Regression:

What the training loop does?

For each polynomial degree:
- Build polynomial features
- Scale them
- Solve the Normal Equation
- Predict on train and test
- Compute MSE
- Plot:
    Fit curve
    Residuals
    Coefficient magnitudes

This gives a complete picture of model behavior.

Understanding the Output:
1. Fit Plot
Shows how well the polynomial curve matches the noisy sine data
- Degree 1: underfitting
- Degree 3: good approximation
- Degree 10: overfitting (wiggly curve)

2. Residual Plot
- Residuals = actual − predicted
- Should be randomly scattered around 0
- Patterns indicate underfitting or overfitting

3. Coefficient Magnitudes
- High degree models often have huge coefficients
- This is a classic sign of overfitting
- Ridge (alpha > 0) would shrink these

Key Takeaways:
1. Polynomial Regression fits curves by adding powers of x.
2. Feature scaling is essential to avoid exploding values.
3. Normal Equation gives a closed form solution.
4. Ridge regularization stabilizes high degree models.
5. Train vs Test MSE reveals overfitting.
6. Coefficient magnitudes visually show model complexity.
7. Polynomial Regression can approximate sin(x) surprisingly well with moderate degree.

Decision Tree:

Goal:
1. Implement a Decision Tree Classifier from scratch (no sklearn).
2. Train it on 2D toy data, test it, print metrics, plot decision boundaries and show underfit vs good fit vs overfit.

Imports:
1. numpy for arrays + math
2. matplotlib.pyplot for plotting decision regions + feature importance bars

Each node stores:

- impurity (gini/entropy at this node)
- num_samples (samples reaching node)
- num_samples_per_class (class counts)
- predicted_class (majority class at node)
- split info:
- feature_index (which feature to split on)
  threshold (split value)
  left, right child pointers
  info_gain (impurity reduction from the split)

Hyperparameters:
- criterion: "gini" or "entropy" (how impurity is measured)
- max_depth: maximum tree depth
- min_samples_split: minimum samples needed to try a split
- min_samples_leaf: minimum samples allowed in each leaf

Learned attributes:
- tree_: root Node
- classes_: unique class labels
- n_features_: number of input features
- feature_importances_: importance score per feature (based on impurity reduction)

Training: fit(X, y):

Steps:
1. Get classes_ and map y into 0..K-1 (np.unique(..., return_inverse=True)).
2. Store n_features_
3. Initialize feature_importances_ = zeros
4. Build tree recursively with _grow_tree(X, y)
5. Normalize feature importances to sum to 1

Prediction: predict(X):

- For each sample x, call _predict_one(x):
- start at root
- if x[feature_index] < threshold go left else right
- stop at leaf and return classes_[predicted_class]

Finding best split: _best_split(X, y)
Purpose: choose (feature_index, threshold) that minimizes weighted child impurity.

For each feature idx:

- Sort samples by that feature value.
- Sweep split point i = 1..m-1:
- skip if consecutive feature values are equal
- enforce min_samples_leaf on both sides
- compute:
  impurity_left = impurity(y_left)
  impurity_right = impurity(y_right)
  weighted impurity = (i*left + (m-i)*right)/m
- Keep split with lowest impurity.
Returns: best_idx, best_thr, best_impurity (child weighted impurity).

Growing the tree: _grow_tree(X, y, depth)
At a node:

Compute class counts and majority class: predicted_class.
Compute current_impurity.
Create a Node(...).
Split only if:
- depth < max_depth
- len(y) >= min_samples_split
- and _best_split returns a valid split
If split found:
- partition with mask X[:, idx] < thr
- store node split info (feature_index, threshold)
- info_gain = current_impurity − child_impurity
- update feature importance:
  feature_importances_[idx] += len(y) * info_gain
- recursively grow left and right

Tree printing: print_tree()
Prints human-readable rules:
IF feature < threshold then left else right
Leaf shows predicted class + sample counts.
